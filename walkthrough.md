# CIRO Nexus: Developer Walkthrough

Welcome to the internal workings of **CIRO Nexus**. This document details the architectural structure, data flow, and key AI features of the platform.

## 1. Architectural Overview

The CIRO platform operates on a **hub-and-spoke model**:
- **Hub (`ciro-backend`)**: Acts as the brain of the operation. It maintains a global, in-memory state of incidents and manages a duplex WebSocket server to dispatch state updates to all connected clients. It also acts as the orchestrator for the AI Swarm.
- **Spokes (`ciro-web-next` & `ciro-mobile`)**: React and React Native frontends that consume WebSockets for real-time UI updates (e.g., Map markers, threat logs) and send HTTP requests to inject telemetry or trigger AI analysis.

## 2. Core Components

### 2.1 The Backend (`/ciro-backend`)
- `main.py`: The entry point. Initializes the FastAPI server, mounts the routers, sets up CORS (to allow Next.js on port 3000 and Expo on 8081), and registers the background autopilot task.
- `database/state.py`: The single source of truth (`GlobalState`). When a signal is added or a crisis is detected, it is appended here. Crucially, the state instance triggers `manager.broadcast(...)` to sync connected clients instantly.
- `database/socket_manager.py`: Handles active WebSocket connections.
- `agents/antigravity.py`: The core AI engine. It contains an orchestration loop (`run_antigravity_pipeline()`) that sequentially runs data through 6 specialized agents:
  1. **Signal Agent**: Normalizes noisy raw inputs into structured metadata.
  2. **Detection Agent**: Looks for patterns in normalized data to declare an emergency type.
  3. **Reasoning Agent**: Performs deep risk analysis (root causes, future predictions).
  4. **Planning Agent**: Recommends resource allocation, traffic plans, and citizen alerts.
  5. **Simulation Agent**: "Executes" the plan virtually and measures the hypothetical post-crisis state.
  6. **Visualization Agent**: Formats the final output for the frontends.

### 2.2 The Web Dashboard (`/ciro-web-next`)
- Built with **Next.js**. The main UI lives in `src/app/dashboard/page.js`.
- Connects to the backend via `ws://127.0.0.1:8000/ws`.
- **NexusMap**: A Leaflet implementation (`src/components/NexusMap.js`) that takes in an array of `allCrises` and maps them to coordinates. It dynamically creates animated CSS pulse markers with distinct colors corresponding to the emergency type (e.g., Red for Fire, Cyan for Floods).

### 2.3 The Mobile App (`/ciro-mobile`)
- Built with **React Native / Expo**. 
- Shares the exact same authentication flow as the web dashboard.
- Uses `src/lib/api.js` to dispatch commands and toggle the Autopilot feature.
- Visual components like `PulseChart` and custom glassmorphism containers mirror the exact visual aesthetic of the Web Dashboard.

## 3. How Features Work

### 3.1 Swarm Cognition (Manual & Autopilot)
1. **Data Ingestion**: Telemetry (signals) can be manually typed in the Dashboard, tapped in the Mobile App, or generated by the `routers/autopilot.py` background loop.
2. **Analysis Trigger**: The frontend calls `POST /api/analyze`.
3. **Pipeline Execution**: The backend invokes the Google Gemini API through the 6 agents. Because the `GlobalState` is updated continuously throughout this pipeline, the frontend displays actions and detections progressively.
4. **History Preservation**: Detections are pushed to `state.crisis_history`, which is broadcasted to the frontend to draw persistent map markers.

### 3.2 Authentication Flow
- Implemented in `routers/auth.py`. 
- Uses `bcrypt` for password hashing and `python-jose` for generating JSON Web Tokens (JWT).
- The frontends store the token in local storage (or secure storage on mobile) and pass it in the `Authorization: Bearer <token>` header for protected endpoints like `/auth/me`.

## 4. Extending the Application
To add a new crisis category:
1. Update `ciro-backend/mock_data.py` to include templates for the new crisis.
2. Update the system prompts in `ciro-backend/agents/antigravity.py` if the AI needs specific instructions on how to handle the new scenario.
3. Add a color mapping in `ciro-web-next/src/components/NexusMap.js` inside the `CRISIS_COLORS` dictionary to give the new crisis a unique map marker color.
